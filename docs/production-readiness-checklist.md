# قائمة جاهزية الإنتاج للمنظومة ERP

## 1. هدف الوثيقة

هذه الوثيقة تحدد ماذا يجب أن يكون متوفرًا قبل اعتماد النظام في الإنتاج بشكل كامل. الهدف ليس فقط أن يعمل النظام، بل أن يكون صحيحًا في الطلبات، المخزون، المحاسبة والتسويات النقدية، مع قابلية الرصد والعودة إلى الحالة الصحيحة عند حدوث أي خلل.

---

## 2. شرط قبول النظام في الإنتاج

يُعتمد النظام فقط عندما تكون جميع البنود التالية محققة:

### 2.1 الطلبات
- [ ] كل طلب يمر عبر WorkflowService فقط
- [ ] لا يوجد تعديل مباشر لحالة الطلب من مسارات خارجية
- [ ] كل انتقال بين مراحل الطلب مسجل في سجل التاريخ
- [ ] لا يوجد طلب يمكن أن يمر من حالة إلى أخرى دون صلاحية قانونية
- [ ] كل طلب له مستودع تنفيذ واضح
- [ ] الطلبات متعددة المستودعات مدعومة بشكل صحيح

### 2.2 المخزون
- [ ] الحجز يحدث قبل الشحن
- [ ] الشحن هو نقطة خروج المخزون الفعلية
- [ ] لا يتم خصم المخزون إلا من خلال الخدمة الرسمية
- [ ] كل حركة مخزون لها سبب ووصف واضح
- [ ] الفرق بين المخزون المحجوز، المنصرف، والفعلي مُدار بشكل واضح
- [ ] لا يُسمح بتحديث المخزون يدويًا دون مراجعة

### 2.3 المحاسبة
- [ ] جميع القيود المحاسبية تدخل عبر LedgerPostingService
- [ ] لا توجد قيود تكتب مباشرة بخصم/إيداع يدوي غير موثق
- [ ] تكلفة البضاعة المباعة تُسجل عند الشحن
- [ ] الإيراد والذمم المدينة تزامن مع مرحلة الطلب المناسبة
- [ ] كل إلغاء طلب ينعكس في الحركة المحاسبية بشكل عكسي

### 2.4 الفواتير والمدفوعات
- [ ] الفاتورة مرتبطة بالطلب الصحيح
- [ ] التسليم لا يساوي بالضرورة الدفع
- [ ] المدفوعات تُسجل عبر مسار موحد
- [ ] المبلغ المتبقي والذمم المدينة تتبع واقع الفاتورة
- [ ] لا توجد فواتير مكررة أو تسوية مكررة

### 2.5 المستودعات
- [ ] لكل مستودع سجل مخزون واضح
- [ ] لكل طلب موصى به مستودع مخصص للتنفيذ
- [ ] مخزون كل منتج يُنفذ وفق مصادر حقيقية وليست تقديرات
- [ ] يمكن التتبع إلى أي مستودع سحب المنتج منه

---

## 3. اختبارات الإنتاج المطلوبة قبل الاعتماد

### 3.1 اختبار دورة الطلب الأساسية
- [ ] إنشاء طلب جديد
- [ ] تأكيد الطلب
- [ ] حجز المخزون
- [ ] تجهيز الطلب
- [ ] شحن الطلب
- [ ] تسليم الطلب
- [ ] تسوية الفاتورة

### 3.2 اختبار إلغاء الطلب
- [ ] إلغاء طلب Pending
- [ ] إلغاء طلب Confirmed
- [ ] إلغاء طلب Processing
- [ ] إلغاء طلب Shipped
- [ ] التأكد من رجوع الحجز والمخزون والقيود المالية

### 3.3 اختبار الطلبات متعددة المستودعات
- [ ] طلب يغطيه مستودع واحد
- [ ] طلب يطلب كمية من مستودعين
- [ ] طلب لا يوجد فيه مستودع واحد قادر على تغطية الكمية كاملة
- [ ] التأكد من أن المخزون المخصص لا يتكرر في أكثر من مستودع

### 3.4 اختبار الجرد
- [ ] مخزون فعلي يساوي المخزون المتاح بعد الحجز
- [ ] عند الشحن يصبح المخزون المتاح أقل بشكل صحيح
- [ ] عند الإلغاء يعود المخزون المحجوز
- [ ] عند الاسترجاع تنخفض/تعود الكميات كما هو متوقع

### 3.5 اختبار المحاسبة
- [ ] عند التأكيد: الإيراد والذمم المدينة مسجلان
- [ ] عند الشحن: تكلفة البضاعة المباعة مسجلة
- [ ] عند التسوية: المدفوعات المسجلة مطابقة للفاتورة
- [ ] عند الإلغاء: القيود العكسية تنفذ

### 3.6 اختبار ربط العميل والموظف والمستودع
- [ ] كل طلب مربوط بعميل صحيح
- [ ] كل طلب مربوط بمستودع تنفيذ صحيح
- [ ] كل طلب مربوط بموظف/مندوب صالح
- [ ] لا يوجد طلب بدون ربط حقيقي للكيانات

---

## 4. مراقبة التشغيل في الإنتاج

### 4.1 تقارير يومية أساسية
- [ ] طلبات معلقة
- [ ] طلبات مؤكدة
- [ ] طلبات قيد المعالجة
- [ ] طلبات مشحونة
- [ ] طلبات مسلمة
- [ ] طلبات ملغاة

### 4.2 تقارير مخزون أساسية
- [ ] فرق المخزون الحقيقي مقابل النظام
- [ ] المخزون المحجوز حسب المستودع
- [ ] المخزون المنصرف حسب الفترة
- [ ] منتجات منخفضة المخزون
- [ ] منتجات لها طلبات معلقة دون تغطية

### 4.3 تقارير مالية أساسية
- [ ] فواتير مفتوحة
- [ ] فواتير متأخرة
- [ ] مدفوعات غير متسعة
- [ ] رصيد العملاء الحالي
- [ ] إجمالي تكلفة البضاعة المباعة
- [ ] الربح الإجمالي حسب الطلبات

---

## 5. سياسات السلامة التشغيلية

### 5.1 الحماية الدائمة
- [ ] لا يُسمح لأي مستخدم بتحديث مخزون بشكل مباشر دون صلاحية خاصة
- [ ] لا يسمح بإنشاء فواتير إلا عبر الطلبات الشرعية
- [ ] لا يسمح بتسوية مدفوعات خارج الفاتورة المناسبة
- [ ] لا يمكن إلغاء الطلب بموجب حالة مزيفة أو حالة غير قانونية

### 5.2 السجلات
- [ ] كل تغيير في حالة الطلب مُسجل
- [ ] كل حركة مخزن لها مرجع
- [ ] كل تشغيل محاسبي له مرجع طلب/فاتورة/دفعة
- [ ] كل خطأ يُسجل في اللوجات للتتبع

---

## 6. معيار القرار النهائي

### يمكن اعتماد النظام في الإنتاج إذا كانت هذه الشروط متحققة:

- [ ] دورة الطلب كاملة ومحققة عبر الخدمة الرسمية
- [ ] المخزون يخرج فقط عند الشحن
- [ ] الحجز يعمل قبل الشحن
- [ ] الفواتير والمدفوعات منسجمة مع الطلب
- [ ] الجرد يطابق الواقع
- [ ] توجد تقارير مراقبة واضحة
- [ ] لا توجد مسارات يدوية تؤثر على نفس البيانات

إذا كانت أي من هذه غير متحققة، فإن النظام لا يزال يحتاج إلى تطوير تحضيري قبل الانتقال إلى الإنتاج الكامل.

---

## 7. التوصية الأخيرة

التوصية العملية هي اعتماد النظام تدريجيًا وليس دفعة واحدة، مع وجود مراقبة حقيقية في أول 2-4 أسابيع، ثم رفع الثقة تدريجيًا. المنطق الحالي قوي، لكن نجاح الإنتاج يعتمد على التنفيذ المنضبط، لا فقط على الكود نفسه.
